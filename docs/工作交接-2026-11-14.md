## 2. 项目目标与边界

### 产品目标

这是一个面向 ComfyUI 的本地提示词工作台。用户通过“快速预设”或“详细设置”选择人物、服装、动作、场景、镜头、风格及内容尺度，右侧实时生成中英文提示词。

### 当前设计方向

- 桌面端优先，主要验收尺寸为 `1920×1080`、`1440×900`、`1280×720`。
- 手机和平板只保证不溢出、可完成操作，不应为了移动端牺牲桌面端效率。
- 视觉方向为克制的 Apple 风格：清晰层级、圆角、轻阴影、低噪声、主操作明确。
- 高级或低频设置使用渐进展开，不把所有字段同时铺在首屏。
- 不删除现有功能，不缩减日常、暗示、私房、开放、露点等既有内容尺度。
- 成人内容仅面向明确成年、虚构、自愿角色；不得加入未成年人、真人冒充或非自愿内容。
- 采用最小直接改动，不为了“顺便优化”添加无关功能。

## 7. 已确认但尚未修复的问题

以下内容是审查结论，不代表已经实施。

### P1：详细设置在高屏桌面端存在 42px 重叠

在 `1440×900` 当前状态下实测：

- `.wizard-bar`：`top=294`、`bottom=383`
- `.form-card.is-active`：`top=341`
- 实际重叠：`42px`
- 页面没有横向溢出，控制台没有错误

根因是历史 `.top-stack { position: sticky; top: var(--topbar-height); }` 与详细模式内部 `overflow:hidden` 工作区叠加。短屏媒体规则会取消 sticky，因此问题主要出现在 900px、1080px 这类较高桌面窗口。

推荐最小修复：只在 `body.details-mode` 下把 `.top-stack` 改为 `position: static; top: auto;`，保留表单卡片标题的内部吸顶。不要全局删除快速模式的 sticky 行为。

### P1：默认人物风格“不指定”时主按钮无法应用

新状态下即使已经选择内容尺度、着装或露点方案，点击“应用选择并更新结果”仍会提示“先选择人物风格”。阻断逻辑位于 `app.js` 的 `applyQuickSelection()` 起始处。

推荐方案：允许人物风格为空，只应用当前已经选择的其他字段。备选方案是禁用主按钮并在按钮旁明确说明前置条件，但不如前者自然。

### P2：“完全离线”文案不准确

当前项目没有 Service Worker 或离线缓存清单。在线版首次打开、刷新或浏览器缓存失效时需要网络，因此“完全离线”不准确。

推荐替换为“数据仅存本机”或“本地处理”。README 开头的“完全离线”也应同步改成“无远程 API、数据本地保存”等更准确表述。

### P2：详细页选项卡键盘行为不完整

七个流程按钮当前都处于 `tabIndex=0`，键盘用户需要逐个按 Tab。应改为：当前项 `tabIndex=0`，其余 `-1`，左右方向键切换，并补齐对应的 `aria-controls` / 面板关联。顶部快速/详细切换已经有方向键逻辑，可复用其模式。

### P2：公开部署包含历史备份文件

- 当前 Git 跟踪约 46 个 `*.bak*` 历史文件。
- 已验证 `app.js.bak-20261113-0202` 可从 GitHub Pages 直接访问并返回 HTTP 200。

这些文件不影响页面运行，但会公开历史源文件、增加仓库噪声并让接手者误用旧版本。建议先移到 `D:\Codex\ComfyUI-Prompt-Studio-archive`，确认备份完整后，再从发布仓库移除并加入 `.gitignore`。不要在未确认目标路径时批量删除。

### P3：详细页顶部仍可进一步压缩

在 `1280×720` 下，详细设置表单实际可视高度约 305px。先修复 P1 重叠，再评估把预设栏和步骤栏各压缩 8–12px；不要为了节省高度移除必要状态或把所有设置塞进一行。

### P3：少数文本框缺少正式可访问名称

一句话输入框和两个提示词文本框主要依赖占位符或邻近文字。可用最小改动补充 `label` 或 `aria-label`，不需要改变界面布局。
