# ComfyUI Prompt Studio · AI 交接文档

最后更新：2026-11-12

## 1. 项目定位

这是一个完全离线、无第三方运行依赖的本地网页提示词工具，用参数化下拉选项为图片、视频和图像编辑模型拼装中英文提示词。

目标模型包括：

- Z-Image Turbo / INT8
- Flux2 Klein
- MOSS Image / MOSS 图像编辑
- MiniMax H3 文生视频 / 图生视频
- Wan 2.2 TI2V-5B / I2V-A14B
- 自定义模型

## 2. 当前状态与硬性约束

- 用户要求先保存在本地，**没有上传 GitHub**。
- README 中仍可能出现旧 GitHub Pages 地址，但它不代表当前版本，接手时不要自行推送或部署。
- 只有用户明确要求后才能上传 GitHub、部署公网或发送链接。
- 所有项目文件应保存在 `D:\Codex`，不要主动写入 C 盘；ComfyUI 自身必需的 C 盘缓存和日志除外。
- 始终使用中文交流。
- 修改前先确认是“仅讨论”还是“实施”；用户已强调不要擅自扩大范围。
- 优先复用成熟的 GitHub 开源方案，采用最小、直接的代码修改。
- 不调用云端 AI、不写入 API Key、不启动额外后台服务。

## 3. 成人内容边界

页面包含明确成人向的图像、视频和服装选项，但必须始终保持以下限制：

- 只允许明确成年、虚构、双方自愿的角色。
- 禁止未成年人、未成年暗示、校园未成年性化、真人 likeness、非自愿和暴力胁迫。
- “可爱”“娇小”“萝莉风格”等在本项目中只能指明确成年角色，内部必须保留成年年龄锚点。
- 半裸、透视、露点和私密身体细节只用于成年人。
- 不要把成人选项改造成可绕过成年限制的通用逻辑。

## 4. 当前界面结构

桌面端采用两栏布局：

- 左侧：快速预设、详细设置和全部参数。
- 右侧：正向英文提示词、中文参考、负面词、JSON、收藏和历史。
- 右侧提示词栏在“快速预设”和“详细设置”切换时始终保留。

顶部命令条包含：

- 一句话描述与本地解析
- 内容尺度：日常 / 暗示 / 私房 / 开放 / 露点
- 画幅锁定
- 简洁模式和重置

顶部快捷预设按以下顺序显示：

```text
人物（人种）  年龄  人物风格  着装
预设服装      整体风格  镜头方案  套用方式
```

右侧按钮：

```text
套用当前
随机
撤销随机
删除（仅自定义人物风格时显示）
```

“人物”是第一级人种/地域面貌选择，不要扩展成复杂的面部民族细分。

下方有两个工作区标签：

```text
快速预设 | 详细设置
```

快速模式只显示顶部预览和当前预设摘要；详细模式显示原来的七步向导，右侧输出栏不隐藏。

露点尺度下会额外显示“露点方案”快捷区，可按场景和露出重点选择完整组合；其他尺度不显示。

露点快捷区包含表现强度、露出重点、场景套餐、姿势预设和成人道具，并支持换姿势、换镜头、换道具、清除道具。

详细设置使用单行紧凑工具条：内容尺度、预设摘要、展开预设、重置、快速/详细切换同排显示。

人物关系快捷入口已完全移除；关系仍通过角色设置里的“关系构成”调整。

## 5. 快速预设的关键规则

- 修改顶部人物、年龄、着装、整体风格、预设服装等，只更新待套用预览。
- 点击“套用当前”后才统一修改底部详细字段。
- 顶部摘要会显示“待套用：…”。
- 顶部选择半裸或全裸时，如果当前尺度不足，摘要会提示“套用时切换露点”。
- 只有点击“套用当前”时才自动把尺度切到露点；随机不会越级改变当前尺度。
- “只应用妆发”不会修改服装，也不会因为顶部半裸/全裸选择而切换尺度。
- 顶部“整体风格”具有最终优先级，不能被人物预设覆盖。
- 自动切换尺度时，会保留用户当前选中的风格和预设服装，不能被该尺度上次保存的选择覆盖。
- “套用当前”和“随机”必须保持分离，选中下拉时不能立即套用整套设置。
- “套用范围”默认 `套用+随机`：点「套用当前」时保留当前已选和已修改的详细字段，只随机补全仍未确定的部分。
- `QUICK_FIXED_FIELDS`、`captureModifiedDetailFields()` 和 `quickProtectedFields()` 共同确定固定项；顶部风格、镜头、露点套餐及其联动动作不能被“其余随机”拆散。
- `userTouchedFields` 与 `randomGeneratedFields` 区分用户主动选择和自动随机值；自动随机值不会在下次套用时被错误锁定。
- 尺度锁会阻止“套用当前”自动切到露点；必须先解锁才能越级套用。
- 露点档包含 17 套场景方案和 7 类露出重点；方案会联动场景、光线、镜头、姿势、朝向、露出方式和身体焦点。
- 露点档还包含 10 套兼容姿势和独立成人道具；道具包含避孕套、情趣玩具、束缚类和辅助用品，只在露点档可见。
- 成人道具通过 `targets` 元数据限制适用的露出重点，避免足部特写出现仅适合后庭或下体的主动使用类玩具。
- 露点方案卡与完整下拉同时存在；随机场景、姿势、镜头和道具使用短期冷却，避免连续重复。
- 无匹配组合会显示空状态，不再留下空白下拉框。
- `currentLoraQuickAffinity()` 会根据当前触发词和启用 LoRA 的名称做轻量场景排序，不展示文件名。
- 随机露点方案只改变待套用预览；点击“套用当前”后才写入详细设置。
- 顶部摘要区分“尚未选择人物风格 / 已选择，待套用 / 待套用 / 已套用”。
- 只保留一个顶层随机按钮；画幅锁定和内容尺度不能被随机意外修改。

## 8. 不能轻易改坏的联动逻辑

### 8.1 半裸服装依赖顺序

应用半裸套装时必须按以下顺序：

```text
裸露区域
→ 透明度
→ 重建遮盖服装和材质选项
→ 遮盖服装
→ 材质、颜色、剪裁
→ 袜型
→ 重建袜类细节
→ 袜类细节和鞋履
```

否则会出现服装为空、材质已写入但主服装没有写入、上一套吊带袜残留等问题。

### 8.2 露点服装不能只保留最高强度

`WARDROBE_SCALE_FIELDS` 是为了让开放/露点档中的服装、袜类和配饰采用累计规则。

不要在露点档只显示最高强度服装，否则普通蕾丝内衣、束腰、薄纱睡袍和正常穿衣会消失。

姿势和动作仍然按露点最高强度筛选，不要把服装的累计规则错误套用到动作字段。

成人道具使用独立 `adultProp` 字段，不要塞回普通 `props` 或 `accessories`。离开露点档时必须清除，避免低尺度提示词残留。

### 8.3 古风情趣服装分组

`fillSelect()` 的 `coveredGarment` 成人分组必须包含“古风情趣”，并保留未列分组兜底。

历史问题是古风服装已进入数据，但展示分组遗漏，导致中国风套装的主服装被静默丢弃。

### 8.4 镜头方案

镜头方案适配同时检查：

- 当前主体人数
- 方案是否成人向
- 是否要求露点
- 是否需要下体可见

阴部特写和肛门特写只能出现在露点尺度，并会联动：

- 景别
- 身体焦点
- 姿势
- 身体朝向
- 露点模式
- 露点动作

不要让日常尺度随机抽到成人或露点镜头。

### 8.5 着装状态

- 内部 `outfitState` 只有 `dressed` 和 `nude`。
- 顶部 `topOutfitState` 有 `dressed`、`half-nude`、`nude`。
- 半裸在内部属于 `dressed` 下的 `half-nude styling`。
- 全裸必须清除袜类和服装细节。
- 从裸体切回穿衣时，应恢复上一次穿衣方式。

## 9. 模式与输出

- 英文提示词是主复制入口。
- 中文提示词继续保留独立复制入口。
- 默认中英文由同一组选项生成。
- “自由编辑”打开后可分别编辑两侧，并明确提示可能不同步。
- H3 使用单一连续镜头、时间轴、机位和音频结构。
- Wan 图生视频会减少人物外貌重复，重点描述运动和物理反馈。
- MOSS 编辑模式强调保持身份、姿势、构图和背景。
- Z-Image、Flux2、MOSS 主要使用自然语言。

## 13. 已知限制

- 页面是结构化提示词拼接器，不是 AI 扩写器；没有配置云端 API 或 Ollama。
- 右侧没有真实生成图片预览，历史概念图中的“画面预览”只是界面示意。
- 自动保存和自定义风格只存在当前浏览器的本地存储中。
- 模型可能仍会生成错字或乱码字形；这不等于网页编码错误，正式文字建议后期叠加。
- README 里的 GitHub Pages 地址可能指向旧版本，未经用户授权不要重新部署或宣称已更新。
